# 科研实现计划

输入为 `FINAL_PROPOSAL.md`、`EXPERIMENT_PLAN.md`、阶段日志和用户授权。计划阶段只读检查仓库，不修改科研源码、不部署、不运行 GPU 实验。

## 检查内容

1. 记录每条 H/Q/M/B/E、来源段落和授权范围。
2. 定位真实存在的文件、函数、入口、数据加载、split、评分路径和已有实验脚本。
3. 区分需要修改、复用和保持不变的输入、处理、输出与接口。
4. 写清 dataset/split、字段变换、分组、样例、命令、配置、预算、种子、资源和原始工件。
5. 为每个阶段列出中间信号、直接相关诊断、推进条件和停止条件。

## 输出

在用户指定的科研项目中生成唯一的 `IMPLEMENTATION_PLAN.md`，包含“方案要求 → 真实实现位置 → 验证证据”的映射。找不到路径或发现计划与仓库不一致时报告阻塞，不虚构入口，也不自行改写研究目标。

实现计划完成后，交由用户批准的实验桥接流程执行。新增重大目标、预算或架构变化需要重新对齐。
