# 科研实现计划

输入为 `FINAL_PROPOSAL.md`、`EXPERIMENT_PLAN.md`、阶段日志和用户授权。计划阶段只读检查仓库，不修改科研源码、不部署、不运行 GPU 实验。

## 检查内容

1. 记录每条 H/Q/M/B/E、来源段落和授权范围。
2. 定位真实存在的文件、函数、入口、数据加载、split、评分路径和已有实验脚本。
3. 区分需要修改、复用和保持不变的输入、处理、输出与接口。
4. 写清 dataset/split、字段变换、分组、样例、命令、配置、预算、种子、资源和原始工件。
5. 为每个阶段列出中间信号、直接相关诊断、推进条件和停止条件。

## 输出

在用户指定的科研项目中生成唯一的 `IMPLEMENTATION_PLAN.md`，包含“方案要求 → 真实实现位置 → 验证证据”的映射。找不到路径或发现计划与仓库不一致时报告阻塞，不虚构入口，也不自行改写研究目标。

实现计划完成后，交由用户批准的实验桥接流程执行。新增重大目标、预算或架构变化需要重新对齐。

## ARIS Codex 实际阶段契约

该 Skill 是 `/experiment-bridge` 的强依赖，必须在实现前执行。先读取 `FINAL_PROPOSAL.md`、`EXPERIMENT_PLAN.md`、`PROBLEM_EVIDENCE_PACK`、Pilot 诊断和当前授权，再扫描真实仓库；输出必须逐项覆盖：

| 标识 | 必须映射的真实信息 |
|---|---|
| H/Q | 假设/学术子问题、来源、直接证据和未验证前提 |
| M | 文件、类/函数、输入输出、依赖和删除/复用边界 |
| B | 版本、配置、数据构建、命令、可复现工件 |
| E | entrypoint、数据/split、预处理、对照、指标、日志、GPU/时间预算、停止条件 |

在 `IMPLEMENTATION_PLAN.md` 中增加“Consistency Check”：检查每个 E 是否回答某个 H/Q、每个 M 是否被某个 E 使用、Pilot 与正式评估是否分开、实现路径是否真实存在。缺失路径、接口或授权时标为阻塞并停止实现计划，不虚构文件或自动扩大研究目标。
